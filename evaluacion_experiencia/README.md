# Experiencia v1: regresión pública

Ocho conversaciones sintéticas y quince oportunidades de desarrollo público. Se derivan de un episodio reportado y variantes mecánicas: lenguaje coloquial, respuesta breve a una pregunta alimentaria, disponibilidad de fresa, orientación de pago, restricción ya conocida, rechazo explícito e intento de añadir precio/identidad. No se guarda la captura, ninguna identidad ni una transcripción privada. No es un conjunto reservado ni demuestra generalización.

Cada turno tiene texto sintético, una respuesta JSON para pruebas offline y un objetivo estructurado externo al candidato. La clase de conversación recibe solamente `turno(texto)`, nunca el objetivo ni una extracción por parámetro. Con `cliente=None`, el evaluador asigna un `ClienteFalso` nuevo por turno; así un atajo local que evite llamar al extractor no desfasa las respuestas siguientes. Los coloquialismos llevan una extracción preparada correcta: pasar offline no demuestra que el modelo los comprenda. El caso de negación breve incorpora deliberadamente una extracción de rechazo incorrecta para comprobar la salvaguarda contextual.

Con un cliente real, no se inyectan respuestas. Todas las llamadas pasan por el cliente existente de `pasteles.llm`; el caller debe mantener el bloqueo y presupuesto acumulado compartidos. Un SDK falso conserva la etiqueta `PRUEBA_EXPERIENCIA_OFFLINE`. La etiqueta real es `EVALUACION_EXPERIENCIA_MODELO`.

El juez comprueba cotización/solicitud exactas, preguntas por campos, eventos de disponibilidad con alternativas disponibles, orientación de `/pagar`, rechazo y bloqueo de inyecciones. Acepta eventos de preguntas nuevos y las frases exactas de preguntas del arnés anterior para no premiar únicamente instrumentación añadida. Las verificaciones léxicas de `/pagar` y peticiones de perfil son limitadas; no certifican naturalidad ni ausencia de cualquier afirmación indebida. No hay juez LLM ni revisión humana inventada.

Hay ocho controles por turno, 120 oportunidades: salida válida, revisión, datos sin nuevas capacidades, cálculo reproducible, pago coherente con cotización fresca, disponibilidad del producto pagable, marcadores sin cobro/reserva y ausencia de peticiones de perfil reconocidas. Los quince objetivos y las ocho conversaciones permanecen en los denominadores aunque una excepción detenga la ejecución. Cero oportunidades se expresa como `None`. Ejecución completa (`EVALUADA`) y cumplimiento automático son campos distintos. Aprobar exige también costo y latencia dentro de criterio y ningún cambio en reservas pendientes; una reserva incierta no equivale a consumo confirmado.

`congelado.json` fija juez, motor, catálogo, criterios y casos antes de medir. No congela el arnés que se corrige: cada reporte registra el SHA-256 del archivo de la clase utilizada, incluido un módulo histórico cargado desde otra ruta. Los resultados anterior/posterior son evidencia de una corrección manual del núcleo, no una promoción automática RSI. No modificar este instrumento después de observar resultados; una revisión exige conservar esta versión e identificar un instrumento nuevo.

API: `evaluar_experiencia(version, cliente=None, salida=None, clase_conversacion=None)`. El caller elige `resultados/experiencia` para real y `resultados/simulacion/experiencia` para offline. Cada corrida crea `experiencia-AAAAMMDDTHHMMSS-<hex10>` con agregados y trazas sintéticas, sin sobrescribir resultados. La prueba es local: no ejecuta Telegram, no aprueba pagos y no mide satisfacción o ventas. La experiencia integral sigue requiriendo revisión humana y recorrido real de transporte y botones.
